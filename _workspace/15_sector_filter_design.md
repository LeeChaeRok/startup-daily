# 15. 분야 숨기기 · 분야로 좁히기 설계

- **작성:** UX 아키텍트, 2026-11-05
- **상태:** 1~5단계 구현·배포(2026-11-05, Q1~Q4 추천안 채택). 6단계(푸시)는 알림을 켤 때 진행한다. 데스크톱 홈은 접기 없이 정렬(−10)만 적용.
- **선행 문서:** 14(분야별 풀 → "내 5곳"). 14 §5의 "발견 1곳은 끌 수 없다"는 결정을 전제로 한다.
- **화면 이름 변경 로그:** 없음. 새로 생기는 요소는 "숨김 섹션(관심 시트 안)", "접힌 행", "숨긴 분야 칩(탐색)" 세 가지다.

## 0. 요약

### 핵심 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | 분야마다 **세 가지 상태(관심 / 보통 / 숨김)** 를 둔다. "이 분야만 보기" 모드는 따로 만들지 않는다. "좁히기"는 관심 시트 안의 바로가기 하나로 처리한다 | 모드가 따로 있으면 관심·숨김·모드가 서로 충돌하는 조합이 생긴다. 상태 3개로 두면 `pick.js`의 입력이 하나로 유지된다 |
| 2 | **숨긴 분야에서는 "오늘의 발견"을 절대 고르지 않는다.** 그 대신 "보통" 분야가 최소 1개는 남아야 한다는 규칙을 둔다 | 발견을 끄지 않겠다는 결정과 숨김을 존중하는 일을 함께 지키는 유일한 방법이다 |
| 3 | **모두의 5곳은 5곳을 그대로 두고, 숨긴 분야만 한 줄로 접는다.** 펼친 행이 3곳보다 적어지면 접지 않고 맨 아래로만 내린다 | 제N호·공유·주간 정리는 featured 5곳 기준이다(14 §1-3). 아예 지우면 "같은 호"라는 정체성이 깨진다 |
| 4 | 탐색과 검색에서는 **숨긴 분야를 기본으로 뺀다.** 다만 분야를 직접 고르거나 회사 이름으로 검색하면 그대로 보여준다. 저장함과 지난 호 목록은 걸러내지 않는다 | 사용자가 명시적으로 찾은 것은 숨기지 않는다. X도 뮤트 단어를 검색 결과에는 적용하지 않는다는 보고가 있다 |
| 5 | 저장 키는 새로 `sd_muted`(배열)를 하나 추가한다. `sd_interests`는 그대로 둔다 | 마이그레이션이 필요 없다. 숨긴 분야가 없는 사용자는 `sd_my_issue` 키도 달라지지 않는다 |

### 사용자가 결정할 열린 질문

| # | 질문 | 추천안 | 대안 |
|---|---|---|---|
| Q1 | 모두의 5곳에서 숨긴 분야를 어떻게 보여줄까 | **한 줄로 접는다**(탭하면 펼친다. 진척 막대의 분모에서 뺀다) | (a) 그대로 둔다(숨김은 "내 5곳"에만 적용) (b) 아예 뺀다. 이러면 제N호와 공유 링크가 사람마다 달라진다 |
| Q2 | "이 분야만 보기" 바로가기를 1차에 넣을까 | **넣는다.** 단, 결과는 "관심 1~N + 나머지 숨김 + 발견용 보통 1개"로 고정한다 | 1차에는 빼고, 숨김 이벤트를 2주 본 뒤에 넣는다 |
| Q3 | 첫 실행 질문(ask/first)에 숨김을 물을까 | **묻지 않는다.** 편집 시트, 상세, 설정에서만 다룬다 | 2단계 뒤에 선택 단계로 3번째 화면을 추가한다(40초 목표가 위험해진다) |
| Q4 | 상세 화면에 "이 분야 숨기기"를 노출할까 | **노출한다.** "같은 분야의 다른 회사" 머리 줄에 작은 텍스트 버튼으로 두고, 되돌리기 토스트를 띄운다 | 시트에서만 바꿀 수 있게 한다. 발견할 수 있는 사람이 적어진다 |

## 1. 모델

### 1-1. 세 상태

| 상태 | 저장 | 내 5곳 | 오늘의 발견 | 모두의 5곳 | 탐색·검색 | 정렬 점수(`personal.js`) |
|---|---|---|---|---|---|---|
| **관심** | `sd_interests` | 4곳의 출처 | 여기서는 고르지 않는다 | 위로 올린다(+10) | 그대로 | +10 + 행동 가중 |
| **보통**(기본) | 둘 다 없음 | 모자랄 때만 채운다 | **출처** | 그대로 | 그대로 | 행동 가중 |
| **숨김** | `sd_muted` (새로 추가) | 넣지 않는다 | **절대 고르지 않는다** | 접는다(Q1) | 기본 필터에서 뺀다 | −10(맨 아래) |

- **배타 규칙:** 한 분야는 한 상태만 가진다. 관심으로 정하면 숨김에서 빠지고, 숨기면 관심에서 빠진다. 같은 시점에 두 저장소를 함께 쓴다.
- **불변식(가장 중요):** `숨김 ≥ 1`이면 `보통 ≥ 1`이어야 한다. 즉, 숨길 수 있는 최대 개수는 `8 − 관심 수`다.
  - 관심을 9개 모두 고른 기존 사용자(보통 0, 발견 없음)는 숨김이 없으므로 이 규칙의 대상이 아니다. 지금 동작이 그대로 유지된다.
  - UI에서 마지막 남은 보통 분야의 숨김 버튼을 막고, 그 이유를 한 줄로 보여준다(§4-2).

### 1-2. 왜 "이 분야만 보기" 모드를 따로 두지 않나

| 검토안 | 장점 | 문제 |
|---|---|---|
| A. 세 상태만 둔다 | 입력 하나, 테스트가 단순하다 | "핀테크만"을 하려면 칩을 7번 눌러야 한다 |
| B. 세 상태 + 별도 "한정 모드" 스위치 | 한 번에 좁힐 수 있다 | 모드를 켠 상태에서 숨김 목록이 무슨 의미인지 설명할 수 없다. 끌 수 없는 발견과 정면으로 부딪친다. `sd_my_issue` 키와 푸시 레코드에 차원이 하나 더 생긴다 |
| **C. 세 상태 + "고른 분야로 좁히기" 바로가기 (추천)** | A의 단순함을 지키면서 B의 한 번 누르기를 얻는다 | 바로가기의 결과가 "보통 1개 남김"이라는 걸 보여줘야 한다 |

- **바로가기의 동작:** 관심이 아닌 분야를 모두 숨김으로 바꾸되, 하나는 보통으로 남긴다.
  - 남길 분야는 행동 가중(`affinityOf`)이 가장 높은 분야다. 동점이면 `SECTOR_KEYS` 순서를 따른다.
  - 남은 칩에는 "발견용" 꼬리표를 붙여서, 사용자가 다른 분야로 바꿀 수 있게 한다.
- **결론:** 저장 모델은 상태 3개 하나뿐이다. "한정"은 그 상태를 한 번에 채우는 UI 동작일 뿐이다.

## 2. 적용 범위별 동작

### 2-1. 내 5곳 (`pick.js`)

`pickMine({ days, interests, muted, isRead })`로 인자를 하나 추가한다. 규칙은 14 §2-1과 같고, 굵게 표시한 부분만 바뀐다.

```
pools   = followedPools(interests)            관심
allowed = SECTOR_KEYS − muted                 숨김이 아닌 분야
① 발견 1곳: 모두의 5곳 중 (allowed − pools)에 속한 가장 강한 회사
          → 없으면 오늘 풀의 (allowed − pools)
          → 없으면 어제·그제 풀의 (allowed − pools) 안 읽은 회사    ← 새로 추가
          → 그래도 없으면 null. 그 자리는 관심 몫이 채운다
② 관심 4곳: 지금과 같다(오늘 → 어제 → 그제, 라운드 로빈)
③ 부족분 채우기: 오늘 모두의 5곳 중 allowed에 속한 회사만 쓴다     ← 숨김은 넣지 않는다
④ 그래도 부족하면: 5곳보다 적게 보여준다. 숨김으로는 절대 채우지 않는다
```

- **관심 없이 숨김만 있는 사용자:** "내 5곳"이 생긴다. 이때 `pools = allowed`이고, 5곳을 모두 라운드 로빈으로 고르며 발견 라벨은 붙이지 않는다.
  - 발견은 "관심 밖"을 정의할 기준이 있을 때만 의미가 있다. 이 사용자에게는 여러 분야를 번갈아 고르는 것 자체가 발견 역할을 한다.
  - 토글은 `interests.length || muted.length`일 때 보인다.
- **되돌아보는 범위는 3일로 유지한다:** 첫 화면 데이터(`latest.json`)가 최근 3일 풀만 담고 있기 때문이다(14 §1-4). 범위를 넓히려면 데이터 파이프라인을 바꿔야 하므로 Later로 미룬다.
- **`sd_my_issue` 키:** `key = pools.join(',') + (muted.length ? '|-' + muted.join(',') : '')`.
  - 숨김이 없으면 키가 지금과 똑같다. 그래서 업데이트한 날 모든 사용자에게 "다시 골랐어요" 토스트가 뜨는 일이 없다.
  - 숨김을 바꾸면 다시 고르고, 기존 토스트 문구를 "분야 설정을 바꿔 오늘의 5곳을 다시 골랐어요"로 넓힌다.

### 2-2. 오늘의 발견

| 상황 | 동작 |
|---|---|
| 숨김 있음, 보통 있음 | 보통 분야에서만 고른다. 숨긴 분야에서는 **절대** 고르지 않는다 |
| "좁히기" 바로가기 사용(보통 1개) | 그 1개 분야에서 고른다. 오늘 0곳이면 어제·그제의 그 분야. 그래도 없으면 발견 없이 관심 5곳 |
| 관심 9개(보통 0, 숨김 0) | 지금과 같다(발견 없음) |
| 숨김만 있고 관심 없음 | 발견 라벨 없음(§2-1) |

- **"끌 수 없다"와 맞추는 방법:** 사용자가 발견을 끄는 스위치는 여전히 없다. 불변식(보통 ≥ 1) 덕분에 발견의 출처는 항상 남는다. 출처 분야가 하루 0곳인 날에만 데이터 사정으로 빠진다.

### 2-3. 모두의 5곳 (Q1 추천안)

```
[행 1] 리페어랩          기후·에너지·푸드 · 독일
[행 2] ...
[행 3] ...
[행 4] ...
┌ 숨긴 분야 1곳 · 핀테크                    보기 ▾ ┐   ← 접힌 행, 44px
└───────────────────────────────────────────────┘
```

- **목록과 순서:** 5곳을 모두 목록에 남긴다.
  - "내 관심 순"이면 접힌 행이 맨 아래로 간다(점수 −10).
  - "발행 순"이면 원래 자리에 접힌 채로 남는다.
- **진척 막대 0/N:** 펼쳐진 행만 센다. 예를 들어 "0/4 · 1곳 접힘"으로 표시한다.
  - `issue_complete`는 펼쳐진 행을 모두 읽었을 때 보낸다. `data.folded`에 접힌 수를 함께 담는다.
- **접지 않는 경우:** 접고 나면 펼친 행이 3곳보다 적어질 때다. 풀이 비공개라 featured 5곳만 있는 기간에는 숨긴 분야가 3개 이상이면 이렇게 될 수 있다.
  - 이때는 접지 않고 맨 아래로만 내리고, 분야 꼬리표 옆에 "숨긴 분야"를 작게 표시한다.
  - 이유: 호 하나가 거의 빈 화면처럼 보이면 "오늘 발행이 실패했나?"로 읽힌다.
- **그대로 두는 것:** 제N호, "이 호 공유" 링크, 주간 정리, 지난 호 목록. 모두 featured 5곳 기준이다.
- **히어로:** 숨긴 분야 회사는 히어로가 되지 않는다. 히어로는 펼쳐진 행 가운데 첫 번째 안 읽은 회사다.

### 2-4. 탐색 · 검색 · 분야 페이지 · 저장함

| 화면 | 동작 |
|---|---|
| 탐색 목록(필터 없음) | 숨긴 분야를 뺀다. 필터 줄 맨 앞에 "숨긴 분야 2개 제외 ×" 칩을 기본으로 켠다. ×를 누르면 이번 방문 동안 모두 보여준다(URL에 `?muted=show`를 붙인다. 해시 쿼리라 정적 호스팅에서도 동작한다) |
| 분야 필터에서 숨긴 분야를 직접 선택 | 그대로 보여준다. 명시적인 의도를 따른다 |
| 검색어 입력 | 이름이나 키워드가 맞으면 숨긴 분야도 결과에 넣는다. 다만 맨 아래로 내리고 "숨긴 분야" 꼬리표를 단다 |
| "분야별로 모아 보기" 선반 | 숨긴 분야 칩은 맨 뒤로 보내고 흐리게 표시한다(텍스트 대비는 AA 유지) |
| 분야 페이지 `#/t/:sector` (숨긴 분야) | 정상으로 보여준다. 맨 위에 "숨긴 분야예요 · 다시 보기" 띠를 둔다 |
| 상세의 "같은 분야의 다른 회사" | 그대로 둔다(사용자가 이미 그 분야의 상세에 들어와 있다) |
| 완독 카드 "오늘 내 분야에 N곳 더" | `moreInMySectors`가 allowed만 센다 |
| "그때 그 회사"(후속) | 숨긴 분야 회사는 건너뛴다 |
| 저장함, 지난 호, 주간 정리 | 걸러내지 않는다. 사용자가 저장했거나 편집된 기록이다 |

### 2-5. 푸시 (`api/push/send.mjs`, 아직 꺼져 있음)

- **구독 레코드:** `muted: string[]` 필드를 추가한다. `subscribe.mjs`에서 `sectors`와 같은 방식으로 검증한다. `syncPushPrefs`가 이 필드도 보낸다.
- **문구 1(공통 호):** 이름은 `issue` 가운데 숨김이 아닌 첫 회사로, 분야 라벨도 숨김이 아닌 분야로 고른다.
  - 예: "11월 5일 호 · 5곳 / 리페어랩 외 4곳 · 기후·에너지·푸드·헬스·바이오"
  - featured 5곳이 모두 숨김이면 회사 이름 없이 "11월 5일 호가 나왔어요"를 보낸다.
- **문구 2(내 5곳):** `pickMine`에 `muted`를 넘긴다. 실제로 고른 수가 5보다 적으면 "외 N곳"의 N을 맞게 고친다. 지금은 "외 4곳"으로 고정돼 있다.
- **건너뛰기:** `onlyInterests` 규칙은 그대로 둔다. 숨김만 있는 사용자는 건너뛰지 않는다.

## 3. 엣지 케이스

| 상황 | 화면 | 처리 |
|---|---|---|
| **숨김 8개** (관심 0, 보통 1) | "내 5곳" = 그 분야 하루 약 3곳 + 어제·그제 안 읽은 것 | 5곳보다 적으면 목록 아래에 상태 카드를 띄운다: "숨긴 분야가 많아 오늘은 3곳이에요 · 분야 설정" |
| **관심 1개 + 숨김 7개**(좁히기) | 관심 4곳 + 발견 1곳(남은 보통 분야) | 관심 분야가 그날 0곳이면 어제·그제로 채운다. 그래도 모자라면 모두의 5곳 중 보통 분야로 채운다. 그래도 모자라면 적게 보여준다 |
| **좁힌 분야가 그날 0곳** | 위와 같다 | 상태 카드: "오늘 핀테크는 쉬어 가요. 어제 못 읽은 2곳을 넣었어요." 생성기의 부족분 기록(14 §1-6)과 같은 원인이다 |
| **5곳보다 적은 날의 탭 이름** | "내 5곳"을 그대로 둔다 | 제목 줄의 숫자(0/3)가 실제 수를 보여준다. 탭 이름이 날마다 바뀌면 손이 기억한 위치가 흔들린다 |
| **풀 비공개 기간**(`public: false`, 공개 데이터 하루 5곳) | "내 5곳" 탭이 없다(지금과 같다) | 숨김은 모두의 5곳 접기와 내리기, 탐색 필터, 정렬에만 적용된다. 시트 설명은 `poolLive`에 따라 바뀐다(§4-4) |
| **비공개 기간 + 숨김 3개 이상** | 접지 않고 내리기만 한다(§2-3) | 펼친 행 3곳 이상 규칙 |
| **새 분야 키 추가·통합**(예: mobility → robotics, 14 §1-6 관문) | 숨긴 키가 사라진다 | `canonicalSector` 매핑을 `sd_muted`에도 적용한다. 통합된 분야 가운데 하나라도 관심이면 숨김에서 뺀다(관심이 이긴다) |
| **기존 저장값 마이그레이션** | 없음 | `sd_muted` 기본값은 `[]`다. 검증은 배열이고 알려진 키만 허용한다. 불러올 때 관심과 겹치면 숨김에서 뺀다. 불변식을 어기면(손으로 고친 저장값 등) 행동 가중이 가장 높은 숨김 하나를 보통으로 되돌린다 |
| **영어판** | 같은 키를 쓴다 | 라벨은 `en` 필드를 쓴다. 문구 초안은 §4-4 |
| **공유 링크로 들어온 상세**(`#/s/`) | 숨긴 분야여도 정상으로 보여준다 | 띠를 띄우지 않는다. 명시적인 방문이다 |

- 숨김 섹션에는 관심이 아닌 분야만 나열한다. 그래서 배타 규칙이 UI에 자연스럽게 드러난다.

- 칩 터치 영역은 최소 44px. 상태는 색만으로 구분하지 않고 아이콘과 `aria-pressed`를 함께 쓴다.

**상세 화면, 같은 분야 섹션 머리**
```
같은 분야의 다른 회사          핀테크 모아 보기 ›
                               이 분야 숨기기
```
- 누르면 바로 반영하고 토스트를 띄운다: "핀테크를 숨겼어요. 내 5곳과 탐색에서 빠져요 [되돌리기]". 토스트는 5초 유지되며, 지금 Toast의 action을 그대로 쓴다.

**홈 · 모두의 5곳(접힌 행)** — §2-3 와이어. 접힌 행을 탭하면 그 자리에서 일반 행으로 펼쳐진다(세션 동안 유지). 펼친 행 아래에 "다시 보기"(숨김 해제) 텍스트 버튼이 붙는다.

| 기존 4종 공통 | — | 본문에 `muted_n`(숨김 개수)을 추가한다. `mine`과 같은 방식으로 `track()`에서 붙인다 |
| `detail_open` 확장 | — | `data.discovery: bool`. 발견 열람률을 숨김 사용자와 아닌 사용자로 나눠 보기 위해서다 |

**볼 지표 (2주)**
- 숨김 사용률(숨김 ≥1인 기기 / 관심 ≥1인 기기).
- 10초 안에 되돌린 비율(`undo`). 30%를 넘으면 상세 버튼이 실수로 눌린다는 뜻이므로 위치를 바꾼다.
- 숨김 사용자의 발견 열람률. 14 §2-4의 기준(관심 몫의 30%)과 비교한다.
- `my_short` 비율. 5%를 넘으면 되돌아보는 범위를 넓히는 일(Later)을 앞당긴다.
- 숨김 사용자와 아닌 사용자의 D7 재방문.
- 저장은 지금처럼 `/api/event`의 함수 로그에만 남긴다. 집계 저장소는 범위 밖이다.

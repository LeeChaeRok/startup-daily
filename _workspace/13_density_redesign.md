# 13. 첫 화면 감량 설계

- **작성:** 리더, 2026-10-31
- **근거:** 사용자 피드백 "텍스트, 컴포넌트가 너무 많다". 실제 기기(iPhone, 다크) 스크린샷 기준이다.
- **시안:** `13_density_mock.html` (지금 화면과 감량안을 나란히 둔다)
- **고치는 문서:** `12_final_spec.md` §6, IA §3, VD §3. 충돌하는 부분은 이 문서가 우선한다.

## 0. 진단

첫 화면(375×812)에 보이는 요소를 셌다.

| 영역 | 지금 | 요소 수 |
|---|---|---|
| 상단 바 | 워드마크, 검색, EN, 테마 | 4 |
| 호 머리 | 날짜·호수, 정체성 문장, "오늘 5곳 · 약 5분", "5곳 중 0곳 읽음", 5칸 막대 | 5 |
| 히어로 | 굵은 괘선, 번호 01, ■, 분야·국가, 로고, 한글 이름, 영문 이름, 굵은 소개 2줄, "AI 코멘트" 라벨, 좌측 선, 코멘트 3줄, 단계, 금액, "읽기 →"와 밑줄 | 14 |
| 행 (한 곳마다) | 번호, 로고, 한글 이름, 영문 이름, 소개, ↗ 아이콘, 왜 지금, ■, 분야, 단계, 국가, 금액 | 12 × 2.5곳 |
| **합계** | | **약 50** |

문제는 네 가지다.
1. **한 회사에 문장이 두 개다.** 소개(무엇)와 '왜 지금'(언제)을 행마다 둘 다 보여준다. 둘 다 말줄임이라 어느 쪽도 다 읽히지 않는다.
2. **같은 정보가 반복된다.**
   - 번호 01~05와 진척 막대가 겹친다.
   - "오늘 5곳"과 "5곳 중 0곳"이 겹친다.
   - 검색 아이콘과 하단 "탐색" 탭이 겹친다.
   - 영문 이름 "Braid"와 한글 "브레이드"는 소리가 같다.
3. **글자 스타일이 너무 많다.** 모노 숫자, 주홍 아이콘, ■ 점, 굵은 소개, 회색 메타, 라벨, 밑줄 CTA가 한 화면에 섞여 있다. 그래서 위계가 보이지 않는다.
4. **카드 전체가 링크인데 "읽기 →"가 또 있다.** 히어로 아래 메타 줄도 행과 같은 정보를 반복한다.

## 1. 원칙

- **한 회사 = 3줄.** 이름, 한 문장, 메타 한 줄. 히어로만 문장 하나를 더 쓴다.
- **글자 스타일은 4가지만.** 제목(굵게), 본문, 보조(회색), 캡션(작은 회색). 모노, ■, ↗, 밑줄 CTA는 첫 화면에서 쓰지 않는다.
- **같은 정보는 한 번만.** 진척은 막대와 "0/5" 하나로 표시한다.
- **상세에 있는 정보는 목록에서 뺀다.** 금액, 단계, 영문 이름, '왜 지금' 전문이 그렇다. 목록의 역할은 "열어 볼지" 고르게 하는 것이다.

## 2. 변경표

| 위치 | 뺀다 / 옮긴다 | 남긴다 |
|---|---|---|
| 상단 바 | 검색(→ 탐색 탭), EN·테마(→ ⋮ 메뉴, 설정) | 워드마크, ⋮(설정·언어·테마·소개) |
| 호 머리 | "오늘 5곳 · 약 5분" 줄, "5곳 중 0곳 읽음" 문장 | 날짜·호수. 그 아래 한 줄에 "정체성 문장 + N곳"(왼쪽)과 "0/5"(오른쪽). 막대는 얇게(3px) |
| 정체성 문장 | 별도 줄 | 호 머리 보조 줄에 합친다: "아직 모르는, 지금 뜨는 스타트업 5곳" |
| 히어로 | 굵은 괘선, 번호, ■, 영문 이름, "AI 코멘트" 라벨·좌측 선, 단계·금액 줄, "읽기 →" | 분야·국가(캡션), 로고 + 이름, 소개(굵게, 최대 2줄), 코멘트(보조색, **2줄**) + 작은 `AI` 표시 |
| 행 | 번호(읽은 행만 체크), 영문 이름, ↗와 '왜 지금' 줄, ■, 단계, 금액 | 로고, 이름, 소개(1줄), 메타 "분야 · 국가" |
| "○○라면" 한 줄 | 첫 화면 히어로에서 뺀다 | 상세 요약 바로 아래에만 둔다 |
| 각주 (목록 아래) | 변경 없음 | AI 작성 고지, 정정 기록 |

## 3. 무엇을 잃고, 어디서 보완하나

| 잃는 것 | 보완 |
|---|---|
| 행의 '왜 지금' | 히어로 코멘트, 상세 첫 블록. '왜 지금'은 열어 본 사람에게 주는 보상으로 둔다 |
| 행의 금액·단계 | 상세 머리. 탐색의 "투자 규모순" 정렬은 지금처럼 금액을 보여준다 |
| 영문 이름 | 상세 머리. 한글과 영문의 소리가 다른 경우(예: "토스" / "Viva Republica")에만 행에 남기는 예외는 두지 않는다. 규칙을 단순하게 하기 위해서다 |
| 히어로의 "○○라면" | 상세. 개인화는 **순서**만으로도 첫 화면에 드러난다 |
| 상단 검색 | 하단 "탐색" 탭이 같은 역할을 한다. 탭을 누르면 검색창에 바로 포커스가 간다 |

- **AI 고지 의무(09 §8):** 히어로 코멘트 옆 `AI` 표시, 목록 아래 각주, 상세에서 계속 유지한다.

## 4. 영향과 범위

- **바꾸는 파일:** `Issue.jsx`(IssueMobile 히어로·머리), `StartupRow.jsx`(`issue` 변형만), `Chrome.jsx`(모바일 상단 바와 ⋮ 메뉴), `app.css`. 데이터는 바꾸지 않는다.
- **데스크톱(≥1024):** 이번 범위에서 제외한다. 이미 3단 레이아웃이라 밀도 문제가 덜하다.
- **영어판:** 같은 규칙을 쓴다. 영문 이름 하나만 표시한다.
- **이 설계를 반영해 고칠 문서**
  - VD §3-4: 행 4줄 → 3줄.
  - VD §3-8: 레버 ②가 기본값이 된다.
  - IA §3-1: 행의 '왜 지금' 결정을 뒤집는다. 근거는 실제 기기에서 확인한 피드백이다.

# 06. "한국에서는" — 유사 사례 + 한국 기회 분석 (설계안)

작성: 2026-10-25 · 상태: 설계 (미구현)

## 0. 무엇을 만드나
회사 상세 페이지에 새 섹션 **"한국에서는"** 을 둔다. 한 회사에 대해 LLM이 다음을 제공한다.
1. **비슷한 것들**: 같은 아이디어·제품·기업(해외 + 한국)과 이 회사와의 관계
2. **한국 현황**: 이미 하는 곳, 규제·시장 특성
3. **기회 가설**: 한국에서 이 사업을 한다면 누가, 어떤 쐐기로, 어떤 장벽을 넘어야 하는가

기존 `competitive_landscape`(이 회사가 *싸우는* 상대)와 다르다. 새 섹션은 *같은 생각이 다른 곳에서 어떻게 구현됐는가*, 그리고 *한국에 옮기면 어떻게 되는가*를 다룬다.

## 1. 가장 큰 위험: "한국에는 아직 없다"
이 콘텐츠의 가치는 "빈자리"를 짚는 데 있고, LLM이 가장 쉽게 틀리는 지점도 거기다. 검색에 안 잡혔다고 없는 게 아니다. 그래서 설계 원칙은 다음과 같다.
- **부재 주장 금지.** "없다"가 아니라 "검색에서 확인되지 않았다"로만 쓴다. 코드에서 단정어("국내에 전무", "유일")를 검사해 걸러낸다.
- **한국 사업자 이름은 검증된 URL이 있어야 노출.** 기존 `verifyLinks`를 재사용한다. 링크가 안 열리면 그 사업자는 목록에서 뺀다. 지어낸 회사명이 사이트에 실리는 것을 막기 위함이다.
- **사실과 가설을 분리해 표시.** 현황은 출처 있는 사실, 기회는 "AI 가설"로 라벨을 붙인다.
- **규제 언급은 법령/기관명 + 출처가 있을 때만.** 없으면 "추정"으로 표시하거나 뺀다.
- 면책 문구: "사업·투자 조언이 아닙니다. 가설이며 검증이 필요합니다."

## 2. 데이터 모델
별도 파일 `src/data/korea-lens.json` (키 = 회사 `id`). `startups.json`과 분리하는 이유: 재생성 주기가 다르고, 번들이 커지지 않게 상세 페이지에서만 동적 import 하려는 것.

```jsonc
"deepfine-deepfine-2026": {
  "generated_at": "2026-10-26T…", "model": "anthropic/claude-haiku-5.5",
  "verdict": "crowded",            // open | emerging | crowded | constrained | unclear
  "headline": "한 줄 결론(60자)",
  "similar": [                     // 3~5개
    { "name": "", "country_ko": "", "relation": "direct | adjacent | analog",
      "kind": "company | product | idea",
      "summary": "이 회사와 무엇이 같고 다른가(2문장)",
      "url": "https://…", "verified": true }
  ],
  "korea": {
    "players": [ { "name": "", "what": "", "url": "…", "verified": true } ],  // 0~4, 검증된 것만
    "market_note": "한국 시장 특성(수요, 구매 구조, 언어, 경쟁 구도)",
    "regulation": { "note": "", "source_url": "…" | null, "estimate": true },
    "search_gaps": "무엇을 찾아봤고 무엇은 확인하지 못했는가"   // 필수
  },
  "opportunity": {
    "thesis": "가설 3~4문장",
    "who": "누가 하면 유리한가(예: 제조 SI, 병원 네트워크 보유 스타트업)",
    "wedge": "첫 진입점",
    "barriers": ["", ""],
    "checks": ["한 달 안에 확인할 것 3개"]
  }
}
```
- `verdict` 정의: `open`=검증된 한국 사업자가 보이지 않음 · `emerging`=초기 플레이어 1~2곳 · `crowded`=여러 곳이 선점 · `constrained`=규제·구조로 진입 장벽이 본질 · `unclear`=근거 부족. **`unclear`가 기본값**이고, `open`은 검색 증거가 충분할 때만 허용한다.

## 3. 생성 파이프라인
기존 일일 생성 뒤에 **3단계**로 붙인다. 이 단계가 실패해도 그날의 호는 발행한다(부가 정보이므로).

```
[기존] 발굴 → 필터 → 회사별 심층 조사 → 링크 검증 → 병합
                                   ↓ 통과한 5곳 각각
[신규] A. 한국 조사 (웹 검색, 한국어 질의)  →  B. 분석 작성 (검색 없음)  →  C. 검증·가드  →  korea-lens.json
```
- **A. 조사 (Haiku, 웹 플러그인).** 입력은 프로필의 `product.summary`, `category`, `business_model`, `target_customer`. 질의 예: "{카테고리} 국내 서비스", "{제품 기능} 한국 스타트업", "{제품} 국내 규제". 출력은 근거 URL이 붙은 사실 목록(JSON)만.
- **B. 작성 (Haiku, 검색 없음).** A의 사실만 입력으로 받아 `similar`, `opportunity`를 쓴다. 검색을 끄는 이유: 작성 단계에서 새 "사실"을 지어내지 못하게 하고, 토큰도 아끼기 위함. 입력에 없는 회사명은 쓰지 말라고 지시한다.
- **C. 가드 (코드).** ① 모든 `url` 검증(`checkUrl`) ② 단정어 정규식 ③ `search_gaps` 비어 있으면 `verdict`를 `unclear`로 강등 ④ `players`가 0이고 근거 검색 수가 적으면 `open` 금지 ⑤ 한글 비율·길이 검사 ⑥ 스키마 검증. 실패하면 1회 재시도, 그래도 실패하면 그 회사는 섹션 없음.
- **모델.** 요청하신 대로 Haiku를 먼저 쓴다. 다만 B(기회 가설)는 판단력이 품질을 좌우하므로, 일주일 정도 결과를 보고 필요하면 B만 Sonnet으로 올리는 선택지를 열어 둔다(`OPENROUTER_MODELS` 같은 별도 변수로).
- **비용(추정).** 현재 하루 약 $0.8~1.0. 한국 조사가 회사당 약 $0.08~0.12이므로 **하루 약 $0.5 추가**. 줄이는 순서: 검색 결과 수 5개로 축소 → 질의 2개로 제한 → 5곳 묶음 1회 호출(품질 하락 위험, 마지막 수단).

## 4. 화면
- 상세 페이지: 기존 순서 `…투자 · 시장` 뒤에 **08 한국에서는** 추가, 섹션 칩/목차에 "한국" 추가.
  1. **결론 박스**: `verdict` 배지 + `headline` + "AI 가설" 태그
  2. **비슷한 것들**: 카드 3~5개(이름 · 나라 · 관계 라벨 · 2문장 · 검증된 링크). 해외와 한국을 나라 표시로 구분
  3. **한국 현황**: 이미 하는 곳(검증된 링크만) · 시장·규제 메모 · "확인하지 못한 것"(`search_gaps`)
  4. **기회 가설**: 누가 / 쐐기 / 장벽 / 한 달 체크리스트
- 목록 행: `verdict`가 `open`/`emerging`이면 작은 배지 "한국 기회". 과하게 눈에 띄지 않게 텍스트 라벨만.
- 탐색: 필터에 "한국 기회" 추가(검색 범위에 `similar[].name`, `korea.players[].name`도 포함 → "토스"를 검색하면 관련 회사가 나옴).
- 디자인: 기존 `callout`, `compare` 표, `tag--warn`, `block__label` 재사용. 신규 컴포넌트 최소화.
- 파일은 상세 진입 시 `import('../data/korea-lens.json')`으로 지연 로드. 데이터가 없으면 섹션 자체를 그리지 않음.

## 5. 기존 회사(과거 호) 처리
- **백필은 최근 호부터.** 최근 3개 호(약 15곳, 약 $1.5)로 시작해 품질을 본 뒤 범위를 정한다.
- 4월 호는 정정 대상이거나 상장·인수 회사가 섞여 있어 **기본은 제외**하고, 요청 시에만 생성한다.
- 갱신: 같은 회사는 90일이 지나거나 `funding.latest_round`가 바뀌었을 때만 재생성.

## 6. 품질 검증
- **샘플 10곳을 사람이 직접 확인**한다(한국 사업자가 실제 있는지, 규제 언급이 맞는지). 오류율이 높으면 B를 Sonnet으로 올린다.
- 자동 점검: 검증된 URL 비율, `unclear` 비율(너무 낮으면 과신, 너무 높으면 쓸모 없음), 단정어 차단 건수를 실행 로그에 출력.
- 오류 제보는 기존 정정 기록(`corrections.json`) 방식을 확장해 `korea-lens` 항목도 정정할 수 있게 한다.

## 7. 단계별 구현 순서
1. 스키마 + UI(목업 데이터 2~3건으로) — 하루
2. 파이프라인 A/B/C + 오프라인 테스트(`--candidates` 방식과 동일하게 모의 응답) — 하루
3. 실제 API로 최근 3개 호 백필 → 샘플 10곳 사람 검증 — 반나절
4. 일일 워크플로에 연결(실패 허용) — 반나절

## 8. 결정이 필요한 것
1. **Haiku만으로 시작**해도 되는가, 아니면 기회 가설(B)만 처음부터 Sonnet으로 할까 → 추천: Haiku로 시작, 1주 뒤 평가
2. **"한국 기회" 배지를 목록에 노출**할까, 상세에서만 보여 줄까 → 추천: `open`/`emerging`만 목록에 작게
3. **백필 범위** → 추천: 최근 3개 호
4. 하루 약 $0.5 추가 비용이 괜찮은가

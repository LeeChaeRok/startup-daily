## 1단계. 분야별 풀 생성 (화면 변화 없음)

### 1-1. 분야 체계 정리

**현재 문제:** `sectors.js`가 자유 텍스트 카테고리를 정규식으로 분류한다. 그래서 브레이드("통신 인프라")가 "AI 인프라·반도체"로 들어갔다. 완전 맞춤에서는 오분류가 곧 "내 분야가 아닌 회사가 온다"는 뜻이다.

**결정**
- 생성 단계에서 LLM이 `sector` 키를 직접 고른다. 목록 밖의 값은 허용하지 않는다.
- 정규식은 키가 없는 과거 데이터를 위한 대체 수단으로만 남긴다.
- 기존 128곳은 한 번 일괄 분류한다. 비용은 $0.1 미만이다.

**풀 묶음 (9개)**
- 데이터: 지난 6개월 분야별 건수.
- 아주 적은 분야는 이웃 분야와 합쳐서 하루 3곳이 채워질 가능성을 높인다.

| 풀 키 | 이름 | 6개월 건수 | 비고 |
|---|---|---|---|
| ai | AI 모델·에이전트 | 18 | |
| infra | AI 인프라·반도체·**개발자 도구** | 15 + 4 | devtools(4건)를 합친다 |
| health | 헬스·바이오 | 19 | |
| climate | 기후·에너지·푸드 | 16 | |
| robotics | 로보틱스·제조 | 12 | |
| mobility | 모빌리티·우주·국방 | 7 | 얇은 분야. 측정 대상 |
| fintech | 핀테크 | 11 | |
| enterprise | 엔터프라이즈·B2B | 17 | |
| consumer | 컨슈머·교육·게임 | 7 | 얇은 분야. 측정 대상 |

- 관심 분야 선택 화면(취향 시트)도 이 9개를 쓴다.
- 지금의 10개 키는 `sd_interests`에 저장되어 있다. 이전 규칙은 `devtools → infra` 하나뿐이다.

### 1-2. 생성 파이프라인 변경

**지금:** 탐색 1회(12곳) → 선정 → 조사 8곳(동시 3개) → 5곳. 13분이 걸린다.

**바꾼 뒤**
```
분야별 탐색 9회 (분야마다 후보 6곳, 동시 3개)
 → 선정 규칙 (유명 회사·중복·단계 확인)
 → 분야별 조사 4곳 = 36회 (동시 6개)
 → 선정 규칙 재확인 → 링크 검증
 → 분야별 최대 3곳 채택 = 풀 약 27곳
 → 공통 5곳 선정 (§1-3)
 → 번역 27곳, 로고, 병합
```

- **시간:** 조사 1회는 약 4~5분이다. 36회를 동시 6개로 돌리면 약 30분이 걸리고, 탐색과 번역을 더하면 약 40분이다.
  - 워크플로 `timeout-minutes`를 30에서 60으로 올린다.
  - OpenRouter의 동시 요청 제한에 걸리면 동시 수를 4로 낮춘다. 그러면 약 50분이 된다.
- **비용 상한:** 환경변수 `MAX_COST_USD`(기본 3)를 둔다. 상한을 넘으면 남은 분야의 조사를 멈추고, 그때까지의 결과로 발행한다.
- **실패 처리:** 한 분야가 3곳을 못 채워도 실패가 아니다. 부족분은 기록만 하고, 측정 지표로 쓴다.
- **"한국에서는" 분석:** 지금처럼 버튼을 누를 때 생성한다. 풀이 커져도 비용이 늘지 않는다.
- **후속 추적(그때 그 회사):** 하루 2곳을 그대로 유지한다. 대상이 늘어나므로, 공통 5곳에 실렸던 회사를 우선한다.

### 1-3. 공통 5곳 = 풀에서 고르기

생성을 따로 하지 않는다. 풀 27곳 중에서 다음 규칙으로 5곳을 고른다.
1. 분야는 서로 달라야 한다(최대 1곳/분야).
2. 국가는 같은 나라 최대 2곳이다. 지금 규칙과 같다.
3. 점수가 높은 순으로 고른다. 점수는 "왜 지금"의 신선도(최근 30일 이내 가점), 링크 검증 수, 그리고 탐색 단계에서 모델이 매긴 주목도(1~5, 새 필드)로 정한다.

- 결과는 `featured: true`로 표시한다. "모두의 5곳", 공유, 주간 정리, 지난 호, 호수(제N호)는 모두 featured를 기준으로 한다. 따라서 1단계 동안 사용자가 보는 화면은 지금과 같다.

### 1-4. 데이터 구조 (필수 선행 작업)

**문제:** 지금은 `startups.json` 한 파일(128곳, 1.28MB)이다. 하루 27곳씩이면 한 달 만에 약 8MB가 되고, 1년이면 수십 MB가 된다. 앱 첫 로딩도 같이 무거워진다.

**바꾼 뒤**
```
src/data/days/2026-10-31.json     그날 풀 전체 (전체 기록)
src/data/index/2026-10.json       그달 목록용 lite 기록 (탐색·저장·검색용)
/data/latest.json (빌드 산출)     최근 3일 풀의 lite + featured 표시
```

- **첫 화면:** `latest.json` 하나만 받는다. 3일 × 27곳 lite면 약 80KB다.
- **상세 화면:** 그날 파일 `days/{date}.json`을 받는다. 지금은 `startups.json` 전체를 받는다.
- **탐색·검색:** 월별 index를 필요할 때 받는다.
- **영어판:** 같은 구조로 `days/en/`, `index/en/`을 둔다.
- **이전 작업:** 기존 128곳은 날짜별 파일로 쪼갠다. 모두 `featured: true`로 둔다. 과거 호는 전부 공통 호였다.
- **생성기:** `merge()`가 그날 파일에 쓰도록 바꾼다. 중복 검사용 기존 목록은 전체 index에서 읽는다.

### 1-5. 1단계 동안 풀의 노출

- **결정:** featured가 아닌 풀 회사는 **2주 동안 공개하지 않는다.** 빌드할 때 공개 데이터에서 뺀다.
- 이 기간에는 품질만 측정한다. 대안("분야 페이지에 바로 노출")은 품질이 확인되기 전에 사용자가 오류를 볼 수 있어서 보류한다.
- 리더나 운영자는 `?preview=pool` 같은 내부 화면으로 풀을 볼 수 있게 한다.

### 1-6. 측정과 관문 (2주 = 14회 발행)

생성기가 매일 `src/data/pool-stats.json`에 분야별로 다음을 기록한다.
- 후보 수
- 선정 탈락 사유(유명, 중복, 단계, 상장·인수)
- 조사 실패 수
- 링크 탈락 수
- 채택 수
- 비용

| 관문 | 기준 | 미달 시 |
|---|---|---|
| 공급 | 각 풀이 14일 중 12일 이상 3곳을 채운다 | 그 풀을 이웃 풀과 합친다. 예: mobility는 robotics로, consumer는 enterprise로 |
| 링크 품질 | 링크 탈락률 5% 이하(지금 2~4%) | 해당 분야의 탐색 프롬프트를 고친다 |
| 사실 오류 | 리더가 풀마다 주 2곳(14일간 약 36곳)을 표본으로 확인한다. 명백한 오류가 10% 이하여야 한다 | 2단계를 보류한다. 원인이 모델이면 풀 조사만 Haiku로 바꾼다 |
| 유명 회사 혼입 | 표본 중 "이미 알려진 회사" 5% 이하 | 회피 목록과 규칙을 강화한다 |
| 중복 | 같은 회사가 2주 안에 다시 뽑히지 않는다 | 중복 검사 범위를 넓힌다 |
| 비용 | 하루 평균 $2 이하 | 조사 수를 분야당 3곳으로 낮춘다 |

## 2단계. 홈 "내 5곳"

### 2-1. 선택 규칙 (클라이언트, 기기 안에서)

```
입력: 관심 풀 P(사용자가 고른 풀 키), 최근 3일 풀, 읽음 기록
관심 풀이 없다 → "모두의 5곳"을 그대로 보여준다(지금과 같다)

내 5곳 =
  ① 관심 몫 4곳: 오늘 풀에서 P에 속한 안 읽은 회사.
     P가 여러 개면 번갈아 가며 1곳씩 고른다(라운드 로빈). 각 풀 안에서는 featured 먼저, 그다음 주목도 순.
     4곳이 안 차면 → 어제와 그제 풀의 안 읽은 관심 회사로 채운다(최대 2일 전까지).
     그래도 모자라면 → 오늘의 모두의 5곳으로 채운다.
  ② 발견 몫 1곳: 오늘의 모두의 5곳 중 P 밖의 회사. 주목도가 가장 높은 곳.
     (P가 모든 풀을 덮으면 오늘 풀 중 주목도 1위)
```

- **결정론:** 같은 날, 같은 관심사면 항상 같은 5곳이 나온다. 정렬 기준만 쓰고 무작위는 쓰지 않는다. 그래야 다시 열어도 목록이 바뀌지 않는다.
- **하루 동안 고정:** 그날 처음 계산한 5곳의 id를 `sd_my_issue`(`{ date, ids }`)에 저장한다. 그날 관심사를 바꾸면 다시 계산하고, 화면에 "관심 분야를 바꿔 오늘의 5곳을 다시 골랐어요"라고 알린다.
- **"발견" 1곳의 목적:** "아직 모르는"이라는 정체성을 지키고, 관심 분야 밖에서 새 관심이 생기게 한다. 이 회사를 읽거나 저장하면 행동 가중치(12 §1-6)에 반영되므로, 고르지 않은 분야도 자연스럽게 순서에 올라온다.

### 2-2. 화면 (13의 감량 구조 위에)

```
10월 31일 · 제23호
[ 내 5곳 | 모두의 5곳 ]        ← 관심 분야가 있을 때만 보이는 2단 토글
아직 모르는, 지금 뜨는 스타트업 5곳     0/5
[히어로]
[행 × 3]
[행: 오늘의 발견]  ← 작은 라벨 "관심 밖에서 하나" (캡션 스타일 하나만 추가)
```

- **진척 막대와 0/5:** 지금 선택된 탭의 5곳을 기준으로 센다.
- **호수(제N호):** 모두의 5곳 기준으로 그대로 둔다. "내 5곳"도 같은 날짜의 호에 속한다.
- **공유:** 회사 공유는 지금과 같다. "이 호 공유"는 모두의 5곳 링크를 보낸다. 내 5곳은 사람마다 달라서 링크로 재현할 수 없기 때문이다.
- **지난 호, 주간 정리:** 모두의 5곳 기준이다. 탐색에 "내 분야 지난 회사" 필터를 둔다. 이 필터는 풀 전체(공개된 이후)를 대상으로 한다.
- **완독 카드:** "내 5곳을 다 읽었어요"를 띄우고, 남은 관심 풀 회사 수를 "오늘 내 분야에 3곳 더 있어요"처럼 보여준다. 탭하면 분야 페이지로 간다. 이로써 풀 27곳이 모두 갈 곳이 생긴다.

### 2-3. 알림 · 위젯

- **알림:** 구독 레코드에 이미 `sectors`가 있다. 서버가 그날 풀에서 관심 회사의 이름을 골라 "기후·에너지 리페어랩 외 4곳"처럼 보낸다. 서버 선택 규칙은 2-1의 ①과 같은 함수를 쓴다(`src/lib/pick.js`를 공유 모듈로 둔다).
- **위젯(1.1):** 내 5곳을 보여준다.

### 2-4. 2단계 측정 (2주)

- 내 5곳 사용자와 모두의 5곳만 보는 사용자를 비교한다.
  - 하루 상세 진입 수
  - 완독률
  - D7 재방문
- "발견" 1곳의 열람률을 본다. 너무 낮으면(관심 몫의 30% 미만) 라벨이나 위치를 바꾼다.
- **선행 조건:** 측정 장치(09 §2의 이벤트 측정)가 없다. 2단계 전에 최소한 Vercel Analytics와 자체 이벤트 4종을 넣는다: 앱 실행, 상세 진입, 완독, 탭 전환.

## 3단계. 첫 실행 질문

- **앱(Capacitor):** 처음 실행하면 첫 화면 전에 전체 화면 2단계(역할 → 분야)를 띄운다. 건너뛸 수 있고, 40초 안에 끝나야 한다.
  - 건너뛰면 모두의 5곳이 홈이 된다.
  - 문구: "고른 분야로 매일 5곳을 골라 드려요. 하나는 관심 밖에서 골라요."
- **웹:** 지금처럼 히어로를 지나 스크롤할 때 띄운다. 웹 방문자는 공유 링크로 회사 하나를 보러 온 경우가 많아서, 바로 질문하면 이탈하기 때문이다.
- **분야 선택 화면:** §1-1의 9개 풀을 쓴다. 각 칩에 "하루 약 3곳"을 적어서, 선택의 결과를 미리 보여준다.

| 오류 제보·정정 | 노출이 늘어 제보가 늘어난다 | 제보는 지금처럼 로그로만 받는다. 1단계 표본 검증으로 미리 거른다 |
| 개인화 순서 (12 §1-6) | 내 5곳에서는 이미 관심 순이다 | 모두의 5곳 탭에만 적용한다 |
| "○○라면" 한 줄 | 변화 없음 | 상세에 그대로 둔다 |
| 탐색·분야 페이지 | 풀이 공개되면 분야 페이지가 매일 3곳씩 늘어난다 | 분야 페이지를 날짜별로 묶어 보여준다 |
| 빌드 시간·배포 크기 | 날짜별 파일로 나눠서 첫 로딩은 오히려 가벼워진다 | §1-4 |
| 회사 페이지 OG (`/s/:id`) | 페이지 수가 하루 27개씩 늘어난다 | 빌드 시간을 확인한다. 길어지면 최근 90일만 정적으로 만들고, 나머지는 앱 안 라우트로 처리한다 |

## 5. 하지 않을 것

- 무작위 추천, 협업 필터링("비슷한 사람이 본"): 사용자가 적어서 의미가 없다.
- 관심 분야 밖을 완전히 막기: "발견" 1곳은 끌 수 없게 한다. 이것이 정체성이다.
- 로그인: 기기 간 동기화 요구가 생기면 그때 붙인다.

## 7. 사용자 결정이 필요한 것

1. **월 예산:** 하루 약 $1.5, 월 약 $45(상한 하루 $3)로 가도 되는지.
2. **1단계 동안 풀을 비공개로 둘지:** 권장은 비공개 2주다. 바로 분야 페이지에 공개하는 대안도 가능하다.
3. **"발견" 1곳을 끌 수 없게 할지:** 권장은 끌 수 없게 하는 것이다. 정체성 문장 "아직 모르는"을 지키기 위해서다.

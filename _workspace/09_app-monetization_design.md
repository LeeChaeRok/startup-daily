## 0. 결론

1. **앱은 처음에 무료로 낸다.** 앱이 맡는 역할은 다음 세 가지이고, 이것이 먼저다.
   - 매일 푸시로 돌아오게 만드는 장치
   - 홈 화면 위젯
   - 스토어 검색 노출
   - 독자가 0명인 지금은 어떤 결제 구조를 써도 매출이 0에 가깝다.
2. **결제는 IAP 구독 하나로 시작한다.** "Startup Daily 멤버", 월 4,900원 / 연 49,000원이다.
   - Apple Small Business Program에 들고 Google 구독을 쓰면 수수료는 15%다. 순수취는 약 77%다.
   - 웹 직접 결제(88%)와 차이는 11%p뿐이다. 반면 앱 안 전환과 심사 안정성을 얻는다.
   - 한국 외부 결제 26%와 광고(AdMob)는 쓰지 않는다.
3. **유료 가치의 중심은 "한국에서는"이다.**
   - 무료: 판정과 헤드라인까지.
   - 멤버: 전체 분석, "내 회사 기준 분석", 30일 지난 아카이브.
4. **앱을 만들기 전에 고쳐야 할 구조 문제가 두 가지 있다.**
   - ① 데이터가 앱 번들에 박혀 있어서, 앱으로 내면 **매일 새 호가 갱신되지 않는다.**
   - ② 유료 콘텐츠가 번들에 들어 있으면 잠글 수 없다.
   - 둘 다 "데이터를 서버에서 받아오기"로 해결된다.

## 1. 앱이 해야 할 일 (심사 통과 조건 겸 리텐션 장치)

Apple 4.2(재포장한 웹사이트 금지) 때문에 웹뷰 래퍼로는 반려될 가능성이 높다. 2026-01에는 네이티브 기능 5개를 넣은 Capacitor 앱도 반려된 사례가 있다. **"웹에 없는 앱 전용 기능"을 처음부터 설계에 넣는다.**

| 기능 | 내용 | 왜 | 구현 |
|---|---|---|---|
| **매일 푸시 1회** | 새 호가 올라오면 "오늘의 4곳: 트레이스위브 외 3곳"을 보낸다. 받을 시간대(아침, 점심, 저녁)를 고를 수 있다 | 리텐션 핵심. 주 1~3회 푸시를 받은 사용자의 90일 리텐션이 34% 높다(2차 자료). 하루 2회 이상은 보내지 않는다 | APNs·FCM. 데일리 워크플로가 배포한 직후 발송 API를 호출한다 |
| **홈 화면 위젯** | "오늘의 스타트업" 4곳의 이름과 한 줄 소개. 탭하면 상세로 바로 이동 | 4.2 대응에 가장 강한 근거. 앱을 열지 않아도 노출된다 | iOS WidgetKit(Swift), Android App Widget. `/api/today` JSON을 주기적으로 갱신 |
| **오프라인 읽기** | 최근 7호와 저장한 회사는 비행기 모드에서도 열린다 | 4.2 대응. 출퇴근 지하철 | 받은 데이터를 기기 저장소에 캐시 |
| **읽음·저장 기록** | 이미 구현됨(2026-10-28). 앱에서는 진동 피드백, 길게 눌러 읽음 표시 추가 | 매일 쓰는 습관 | 기존 코드 재사용 |
| **네이티브 공유** | 공유 시트, 카카오톡 공유 | 유입 | Capacitor Share |

**포장 방식 결정: iOS와 Android 모두 Capacitor로 만든다.** TWA(Bubblewrap)는 Android에서는 더 빠르다. 하지만 위젯과 네이티브 푸시를 양쪽에 똑같이 만들려면 코드베이스가 하나인 쪽이 낫다. 지금 React 코드는 그대로 쓴다.

## 2. 앱 전에 고칠 구조 (Phase 0)

| 문제 | 현재 | 바꿀 것 |
|---|---|---|
| 데이터 갱신 | `startups.json`이 빌드할 때 번들에 들어간다. 웹은 매일 재배포하니 괜찮지만, 앱은 스토어 업데이트를 해야만 새 호가 보인다 | 앱 시작 시 `/data/latest.json`(최근 30호)을 받아온다. 실패하면 마지막 캐시를 쓰고, 그것도 없으면 번들에 든 초기 데이터를 쓴다. 웹도 같은 방식으로 바꿔 번들 크기(1.2MB)를 줄인다 |
| 유료 콘텐츠 잠금 | `korea-lens.json` 전체가 번들에 들어 있다 | 번들과 공개 JSON에는 판정·헤드라인 같은 미리보기 필드만 둔다. 전체 분석은 `/api/korea-lens`가 멤버 권한을 확인한 뒤 내려준다 |
| 아카이브 | 30호가 지나면 데이터에서 지운다 | 모두 보관한다. 30일이 지난 호는 `/data/archive/{yyyy-mm}.json`(공개 목록 + 멤버 본문)로 분리한다 |
| 푸시 시각 | cron이 07:37 예정이지만 GitHub 지연으로 실제로는 10:36에 실행된다 | cron을 05:00 KST로 당긴다. 늦어져도 8시 전에 끝나게 하기 위해서다. 푸시는 배포가 끝난 뒤 보내므로 시각이 밀려도 틀린 알림은 나가지 않는다 |
| 측정 | 없음 | 이벤트 측정을 넣는다: 앱 실행, 상세 진입, 한국 분석 요청, 페이월 노출과 탭, 푸시 동의와 열람. 웹은 Vercel Analytics, 앱은 같은 이벤트를 자체 API로 보낸다 |

## 3. 상품과 가격

### 3-1. 무료와 멤버의 경계

| | 무료 | 멤버 |
|---|---|---|
| 오늘 호 + 최근 30일 | 전부 | 전부 |
| 회사 상세 7개 섹션 | 전부 | 전부 |
| 읽음·저장·푸시·위젯 | 전부 | 전부 |
| **한국에서는** (공용 분석) | 판정 + 헤드라인 + 한국 회사 1곳 | 전체: 해외 유사 제품, 한국 회사 전부, 기회·리스크, 출처 |
| 새 분석 요청 (아직 없는 회사) | 월 3건 | 월 30건(공정 사용) |
| **내 회사 기준 분석** | – | 월 10건. 내 회사·아이디어·직무를 입력하면 "이 회사가 나에게 주는 의미"를 분석한다. 사용자별 생성이라 실제 원가가 든다 |
| 30일이 지난 아카이브 | 목록과 한 줄 소개만 | 전체 |
| 섹터·회사 팔로우 알림 | – | 후속 투자·뉴스가 생기면 푸시 |

경계 원칙:
- **매일 읽는 습관(오늘 호, 상세, 푸시)은 절대 잠그지 않는다.**
- 잠그는 것은 "더 깊게"와 "나에게 맞게"뿐이다.
- 이 근거로 하드 페이월(앱 첫 실행 때 결제 화면)은 쓰지 않는다. 하드 페이월의 35일 전환율이 10.7%로 소프트(2.1%)보다 높다는 데이터는 있다. 하지만 독자도 신뢰도 없는 매체가 첫 화면을 막으면 설치 후 이탈만 생긴다. **소프트 페이월로 시작한다.** 하드 페이월 실험은 MAU 5천 명 이상일 때 A/B로 검토한다.

### 3-2. 가격

| 상품 | 가격 | 비고 |
|---|---|---|
| 멤버 월간 | 4,900원 | 롱블랙(5,900원)보다 낮게 둔다. 대중성이 더 낮은 주제라서다 |
| 멤버 연간 | 49,000원 | 2개월 무료 효과 |
| 무료 체험 | 연간 상품에 **7일 체험**(스토어 소개 혜택) | 스토어가 결제 전 고지와 동의를 처리한다. 월간에는 체험을 두지 않는다 |
| 웹 가격 | 앱과 같게 | 앱 안에서 "웹이 더 싸다"는 안내는 한국 스토어에서 금지(3.1.3)다. 가격 차이는 신뢰 비용이 더 크다 |

**소모성 IAP(분석권)은 나중에 둔다.** 멤버십 전환이 낮고 "내 회사 기준 분석" 단건 수요가 보일 때만 "분석 5건 2,900원"을 추가한다.

### 3-3. 앱 밖 수익 (07에서 유지)

- **B2B 섹터 스카우팅 노트**: 사내 열람 월 30만 원, 협력사 전달 포함 월 60만 원. 웹과 PDF로 제공하고 세금계산서를 발행한다. 앱과 무관하며, 독자 수와 관계없이 매출을 낼 수 있는 유일한 경로다.
- **스폰서**: 푸시 동의 사용자 5천 명 이상일 때. 앱 피드 안 1칸에 "스폰서" 표기를 한다. 돈을 받고 소개 회사를 고르지 않는다.
- **하지 않음**: AdMob 광고(DAU 1천 명이어도 월 약 20만 원, 신뢰 훼손), 제휴 링크, 유료 투자 Q&A 커뮤니티.

## 4. 결제 구조 (Phase 2)

```
iOS 앱  ─ StoreKit IAP(SBP 15%) ─┐
Android ─ Play Billing(15%)  ────┼→ RevenueCat ── 권한 "member" ─┐
웹(후순위) ─ 토스/포트원 ─ 웹훅 ─┘   (프로모션 권한 부여 API)      │
                                                                  ▼
                       /api/* 가 RevenueCat REST로 app_user_id의 권한 확인
                       (결과를 Upstash Redis에 10분 캐시)
```

- **계정**: 처음에는 로그인 없이 RevenueCat 익명 ID와 "구매 복원"으로 시작한다. 웹 결제나 기기 간 동기화가 필요해지면 로그인을 붙인다.
  - 로그인 수단: Apple 로그인과 카카오 로그인. 카카오 같은 제3자 로그인을 넣으면 Apple 로그인도 반드시 함께 제공해야 한다(가이드라인 4.8).
  - 계정을 만들면 **앱 안 계정 삭제** 기능이 필수다.
- **RevenueCat**: 월 매출 2,500달러(약 350만 원)까지 무료다. 웹 결제 매출은 RevenueCat 지표에 잡히지 않으므로 따로 집계한다.
- **웹 결제는 앱 결제가 자리 잡은 뒤에 붙인다.** 처음부터 두 경로를 운영하면 1인 운영 부담이 크다.
- **Google 신규 수수료 체계**(한국은 2026-12-31까지 적용 예정이라는 보도)가 시행되면 구독 수수료가 10%로 내려간다. 자체 결제 병행은 PCI-DSS 부담 때문에 보류한다.
- **방미통위 안티스티어링 시정명령**(2026-10-28 심의, 결과 미확인)이 나오면 iOS 안에서 웹 결제를 안내할 수 있게 된다. 그때 웹 결제를 다시 검토한다.

## 5. 화면 설계 (앱 기준 변경점)

| 화면 | 변경 | Phase |
|---|---|---|
| 첫 실행 | 3장 온보딩 없이 바로 오늘 호를 보여준다. 첫 상세를 읽고 나오면 **푸시 권한 사전 안내 카드**를 띄운다("매일 아침 한 번, 오늘의 4곳만 알려드려요"). 사용자가 탭할 때만 시스템 권한 창을 연다 | 1 |
| 설정(새 화면) | 알림 시간대, 알림 끄기, 테마, 읽음 기록 초기화, 구매 복원, 멤버십 관리(스토어 구독 관리로 연결), 개인정보·약관, AI 고지 | 1 |
| 상세 · 한국에서는 | 미리보기 다음에 "전체 분석" 경계를 둔다(페이드로 처리, 블러 금지). 탭하면 **멤버십 시트**를 연다 | 2 |
| 상세 · 내 회사 기준 분석 | 한 줄 입력과 버튼. 무료 사용자에게는 예시 결과 1개를 보여주고 멤버십 시트로 연결 | 2 |
| 멤버십 시트 | 포함 기능 4줄, 월/연 토글(연간에 "7일 무료" 표기), 결제 버튼 1개, 구매 복원, 약관·자동갱신 고지(스토어 필수 문구) | 2 |
| 탐색 · 아카이브 | 30일이 지난 호에 작은 잠금 표시. 목록과 한 줄 소개는 보인다 | 2 |
| 위젯 | 소형: 오늘 호 회사 수 + 첫 회사 이름. 중형: 4곳 이름과 한 줄 소개 + 읽음 체크 | 1 |

디자인 원칙(07에서 유지): 잠금은 조용하게 처리하고, 주홍 강조색은 결제 버튼에만 쓴다. 팝업은 자동으로 띄우지 않고, 사용자가 누른 곳에서만 연다.

## 6. 단계와 전환 조건

| Phase | 내용 | 비용 | 다음 단계로 가는 조건 |
|---|---|---|---|
| **0. 구조 정리** (웹, 1~2일) | 데이터 원격 로딩, 미리보기·전체 분리, 아카이브 보관, cron 앞당김, 이벤트 측정 | 0원 | 완료 즉시 |
| **1. 무료 앱 출시** | Capacitor 앱(iOS·Android), 푸시, 위젯, 오프라인, 설정. **Android 비공개 테스트 12명 × 14일**은 개인 계정이라면 필수다. 테스터 모집을 Phase 0과 동시에 시작한다 | Apple 연 99달러, Google 25달러(1회) | 설치 1천 명 이상, 7일 리텐션 15% 이상, 푸시 동의 35% 이상 |
| **2. 멤버십** | 사업자등록(간이과세 검토) → 스토어 유료 계약 → IAP + RevenueCat → 잠금 적용 | 사업자등록 0원, RevenueCat 무료 구간 | 3개월 유지 판단: 유료 50명 이상, 월 해지율 10% 이하 |
| **2'. B2B 노트** (병행) | 샘플 리포트 3종, 직접 영업 | 0원 | 첫 고객 1곳 |
| **3. 스폰서·웹 결제** | 푸시 동의 5천 명 이상일 때 | – | – |

**숫자 감각(추정):**
- 개인 멤버십: MAU 5천 명 × 전환 2% = 유료 100명 × 4,900원 × 77% = **월 약 38만 원**이다.
- 같은 시점에 B2B 2곳이면 월 60만~120만 원이다.
- 개인 멤버십은 매출보다 "제품 가치의 신호"로 본다. 실제 돈은 B2B에서 먼저 들어올 가능성이 높다.

## 7. 등록과 신원 노출 (결정 필요)

| 항목 | 개인으로 등록 | 사업자(간이과세)로 등록 |
|---|---|---|
| Apple 판매자명 | **실명이 노출된다** | 개인사업자도 실명이 노출된다. 브랜드명으로 노출하려면 법인과 D-U-N-S 번호가 필요하다 |
| Apple 유료 판매 | 한국 개인 계정에 사업자등록번호를 요구한 사례가 있다. **사실상 불가로 본다** | 가능. 제품 페이지에 사업자등록번호가 표시된다 |
| Google 유료 판매 | 결제 프로필의 **전체 주소가 공개**된다 | 같음. 사업장 주소를 집 외의 곳(비상주 사무실 등)으로 둘지 검토한다 |
| Google 출시 요건 | 테스터 12명 × 14일 비공개 테스트 | 조직 계정은 면제라는 2차 자료가 있다(공식 확인 불가) |

**권장:**
- Phase 1(무료 앱)은 개인 계정으로 낸다. 무료 앱은 사업자등록번호 없이 가능해 보인다.
- Phase 2 직전에 사업자등록을 하고 유료 계약을 맺는다.

## 8. 리스크

| 리스크 | 대응 |
|---|---|
| iOS 4.2 반려 | 위젯·푸시·오프라인을 1차 제출부터 넣는다. 리뷰 노트에 "웹에 없는 기능" 목록을 적는다. 반려되면 핵심 흐름(저장, 읽음, 설정)을 네이티브 화면으로 옮긴다 |
| AI 분석 크레딧의 IAP 해당 여부 | 멤버십(IAP)으로만 팔기 때문에 문제가 없다. Reader 모델(앱 결제 없이 웹 결제만)은 "기능 잠금 해제"로 보일 위험이 있어 쓰지 않는다 |
| 유사투자자문업 | 유료 콘텐츠에 투자 권유형 표현을 금지한다. "한국 기회"는 사업 기회로만 서술한다. 쌍방향 유료 채널은 운영하지 않는다 |
| AI 기본법 표시 | 앱 설정, 첫 실행, 공유 이미지에 "AI 생성" 표시 |
| 데이터 오류가 유료 콘텐츠에 섞임 | 정정 로그 공개, 링크 검증 유지, 멤버에게 오류 제보 버튼 제공 |

## 9. 사용자 결정이 필요한 것

1. **스토어 계정 명의**: 개인 실명으로 낼지, 처음부터 사업자로 낼지.
2. **Android 테스터 12명 모집**: 지인이나 커뮤니티로 모을 수 있는지. 어려우면 iOS를 먼저 낸다.
3. **Phase 0 착수 여부**: 데이터 원격 로딩, 잠금 준비, 아카이브 보관, cron 05:00, 측정. 웹에도 바로 이득이 있는 작업이다.
